# TASK-017: фиксированные роли текущего семестра в боте

## Решение и граница

Владелец подтвердил: учебный справочник пяти CRISP-DM-ролей принадлежит боту,
передаётся в 4К как контекст проекта и роли, не создаёт справочник учебных ролей
в 4К. Учебную роль можно назначить раньше сопоставления с опубликованной
`RoleProfileVersion` 4К. Пока точного ID/checksum нет, создание назначения оценки
закрыто. Это не меняет контракт оценки 4К и не разрешает выпуск API-ветки 4К.

## Источник → правило → реализация → проверка

- Источник: `ТГ бот для студентов.md`, раздел «Детализация таблицы ролей в проекте
  по методологии CRISP-DM», SHA-256
  `bc72e53d67675cfcedcec36d2376d3f6540dbced99723c50f99f2dc3e1159776`;
  решение владельца в текущем обсуждении.
- Правило: только пять фиксированных ролей для новых учебных проектов; описание
  и взаимодействия версионируются в каталоге бота, а не в исходном Python-коде.
- Артефакт: `app/artifacts/crisp_dm_roles/2026/manifest.json`, версия `2026.1`,
  `roles.json` SHA-256
  `5356305d2be95b78abad28e80ca676ea482c6e129c7719f5c44b1ba6a3a0eec8`.
- Реализация: `/roles` показывает каталог; `/new_role` и `/publish_role` удалены
  из Telegram; создание проекта атомарно добавляет пять published-версий без
  mapping 4К; `/assign_role` принимает только каталожный код;
  `/assign_assessment` требует опубликованную роль 4К, иначе не пишет Assignment.
- Проверка: checksum loader, handler и PostgreSQL integration на пять версий,
  локальное назначение до mapping и fail-closed оценивание.

## Совместимость и открытые границы

Опубликованные версии и старые назначения не изменяются. Старый внутренний
`RoleService.create_draft/publish` сохранён для совместимости, но Telegram-команд
к нему нет; это не пользовательский способ вводить другие роли. Уже существующие
проекты не заполняются автоматически. Отдельный механизм preview/apply описан в
`task-018-catalog-backfill.md`; рабочие данные не мигрировались. Также
контракт сопоставления локального снимка с опубликованной `RoleProfileVersion`
4К без переписывания опубликованной версии описан в
`task-019-role-profile-binding.md`. До опубликованного проверенного
сопоставления обхода допуска нет.
