# TASK-018: безопасное добавление каталога в существующий проект

## Результат и граница

Добавлен локальный механизм для существующего учебного проекта: read-only план
показывает отсутствующие, уже совпадающие и конфликтующие роли. Применение требует
точный отпечаток просмотренного состояния, блокирует строку проекта и добавляет
только отсутствующие роли в одной транзакции. При конфликте или устаревшем плане
не пишет ничего. Только активный администратор-создатель проекта имеет доступ.
Автоматического обхода всех проектов и запуска на рабочей базе нет.

## Источник → правило → реализация → проверка

- Источник: решение владельца о пяти фиксированных ролях текущего семестра,
  `task-017-fixed-semester-roles.md`, каталог `2026.1` с checksum
  `5356305d2be95b78abad28e80ca676ea482c6e129c7719f5c44b1ba6a3a0eec8`.
- Правило: опубликованные роли, назначения и контексты оценки не переписываются;
  столкновение по коду роли требует ручного решения, не автоматического merge.
- Реализация: `ProjectService.preview_catalog_backfill` и
  `ProjectService.apply_catalog_backfill`; операторский вход
  `python -m app.catalog_backfill` с обязательными проектом и actor ID. `--apply`
  требует `--expect-fingerprint`; `DATABASE_URL` задаётся явно в окружении.
- Проверка: синтетический старый проект без ролей, повторное применение,
  конфликтующая старая роль, устаревший отпечаток и чужой администратор.

отдельное решение о выпуске. Конфликтующий проект остаётся без изменений до
отдельного решения. Клиент 4К и общий Telegram-канал не подключаются.

## Откат

версии SQL-операцией: они могут быть уже назначены. Для ошибочно добавленного

по точным IDs и audit events; восстановление БД только из проверенной копии.
