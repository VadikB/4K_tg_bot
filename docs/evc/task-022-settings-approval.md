# TASK-022: понятные настройки и утверждение кнопкой

Основание: владелец попросил заменить технические термины понятным описанием
настроек и кнопку «Утвердить настройки» вместо ручного /publish_spec с кодом.
После выбора получателей /new_spec показывает проект, выбранную конфигурацию,
число кейсов, период и получателей; checksum/runtime остаются внутренними полями.
Кнопка содержит проект и точную версию. Callback проверяет личный чат, доступ
к проекту и административные права. Сервис блокирует выбранный draft; старая
кнопка не утверждает новую версию. Повтор не создаёт второй audit event.
/specs также показывает кнопку для существующего draft. Старая команда совместима.
4К API, методология и опубликованные снимки не меняются. Утверждение не запускает оценку.

Проверки: Ruff/mypy PASS; pytest 98 PASS / 23 SKIP без локальной изолированной БД.
Регрессия handler: текст, точная версия, запрет чужого проекта; integration
проверяет старую кнопку при новом draft, выполняется CI на bot_pytest.
Откат: revert PR; необязательный expected_version совместим со старой командой.
Merge/deploy требуют отдельного поручения владельца.
