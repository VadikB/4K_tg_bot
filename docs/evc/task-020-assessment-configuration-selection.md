# TASK-020: выбор конфигурации 4К из списка

## Результат

`/new_spec` показывает доступные проекты, затем опубликованные конфигурации 4К
кнопками. Бот сохраняет точные `ref`, `reference_checksum` и `methodology_ref`
из ответа 4К; ручной ввод этих значений убран. Число кейсов, период и получатели
остаются локальными настройками проекта. Существующая публикация локального
snapshot и назначение оценки сохраняют прежние версии и ссылки.

## Источники и решение

- Base bot commit: `35f70034d93baeedb3dff698f59c8ae2dd970986`.
- 4К: TGBOT-02/04 и новый read-only
  `GET /integration/v1/assessment-configurations` в ветке
  `codex/assessment-options-main`, commit `5a26057e`, на базе 4К `main`.
- Решения владельца 20.11.2026: показывать список опубликованных конфигураций;
  не менять спецификации 4К; число кейсов, период и получателей оставить
  локальными настройками проекта; обращаться только к стенду `test`.
- 4К остаётся владельцем конфигурации и runtime. `reference_checksum` фиксирует
  набор её опубликованных ссылок, а не является предметной настройкой бота.

## Границы и проверка

Выбор повторно читает список перед сохранением; устаревшая кнопка и недоступный
4К завершают сценарий без создания локального snapshot. Для рабочего окружения
бота HTTP-режим допускает только `https://test.4k-assistant.ru`.

Unit/handler/HTTP adapter, Ruff, mypy и `git diff --check` выполняются до PR.
Integration/Telegram против общего `test`, CI и выпуск требуют совместимого API
4К и отдельного решения по Student Channel. Участник без связанного
`agent4k_user_id`, опубликованной M3-привязки и admission не получает Case.

## Откат

Вернуть прежний обработчик `/new_spec`, сохранив созданные локальные published
snapshots и назначения без изменения. Настройка сервера возвращается к
`AGENT4K_INTEGRATION_MODE=disabled`.
