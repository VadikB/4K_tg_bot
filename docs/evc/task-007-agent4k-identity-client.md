# TASK-007: клиент связи участника с пользователем 4К

## Результат

После принятия Telegram-приглашения бот вызывает сервисный identity-link endpoint 4К
и сохраняет `agent4k_user_id`. Недоступность 4К не откатывает вступление в проект;
участник повторяет операцию командой `/link_4k CODE`.

## Область

- Включено: HTTP-клиент `POST /integration/v1/participants/resolve`, автоматическая
  попытка после приглашения, ручной retry, транзакционное сохранение ID и аудит.
- Не входит: организация, профиль, Assessment Cycle, Case, Results и email-верификация.

## Источники и решения

- Основание: решение владельца от 06.11.2026 использовать email как технический мост.
- Base: `c333e5f` (TASK-006).
- Серверный контракт: ветка 4К `codex/tg-bot-identity-link`, commit `c4b11789`,
  `POST /integration/v1/participants/resolve`.
- Бот не передаёт Telegram ID и не получает email в ответе. Общий Bearer-токен
  берётся только из `AGENT4K_API_TOKEN` в `.env`.
- Внешний вызов выполняется вне транзакции PostgreSQL; перед записью строка блокируется,
  локальная identity/email проверяется повторно. Повторный вызов не обращается к 4К,
  если связь уже сохранена.
- В audit сохраняются внутренний ID и технический статус, но не email и не токен.

## Критерии приёмки

- [x] HTTP-клиент соответствует серверному request/response.
- [x] Отключённый/недоступный адаптер закрыт ошибкой без fallback.
- [x] Вступление в проект не откатывается при недоступности 4К.
- [x] ID сохраняется только участнику текущей Telegram identity.
- [x] Повторное связывание идемпотентно.
- [x] Администратор видит состояние связи без вывода email или внутреннего ID.

## Откат

Отключить `AGENT4K_INTEGRATION_MODE`, вернуть обработчик приглашения и команду.
Сохранённые `agent4k_user_id` не удалять автоматически; они ссылаются на реальные
строки 4К и не влияют на локальное участие в проекте.
