# 4K TG Bot

Telegram-бот учебных проектов по CRISP-DM с подключением оценки 4К.

Проект хранит учебные проекты, участников, версии проектных ролей, спецификации
оценки и назначения. Предметная оценка 4К остаётся во внешнем сервисе и вызывается
через адаптер; бот не рассчитывает уровни компетенций самостоятельно.

## Статус

Работают административные пути карточки проекта и участников: bootstrap-администратор
регистрируется по `/start`, создаёт проект, выпускает одноразовую ссылку участнику,
а участник связывает Telegram identity с проектом через эту ссылку. При приглашении
администратор задаёт email: он нормализуется для будущего поиска пользователя 4К,
но не считается подтверждённым и не передаётся в оценочный snapshot.
Интеграция с 4К по умолчанию выключена. В режиме `mock` разрешены только локальная
разработка и тесты.

## Быстрый старт

```bash
/usr/local/bin/python3.12 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
cp .env.example .env
docker compose up -d db
alembic upgrade head
python -m app.main
```

Добавьте Telegram ID первого администратора в
`BOOTSTRAP_ADMIN_TELEGRAM_IDS`. Токен бота хранится только в `.env`.

## Команды администратора

```text
/start        регистрация и определение прав
/new_project  пошаговое создание карточки проекта
/projects     доступные проекты
/add_participant  создать одноразовое приглашение
/participants CODE  участники проекта
/link_4k CODE  повторить связь текущего участника с 4К
/new_role     создать новую версию CRISP-DM-роли
/publish_role PROJECT ROLE  опубликовать роль
/roles PROJECT  версии ролей проекта
/assign_role PROJECT PARTICIPANT_ID ROLE  назначить роль
/my_roles     роли текущего участника
/new_spec     создать draft спецификации оценки
/publish_spec PROJECT  опубликовать локальный snapshot
/specs PROJECT  версии спецификации
/assign_assessment PROJECT PARTICIPANT_ID ROLE  назначить оценку
/progress     прогресс участника
/cancel       отмена текущего диалога
```

Bootstrap не делает все новые аккаунты администраторами: право получает только
точный `telegram_user_id` из `BOOTSTRAP_ADMIN_TELEGRAM_IDS`.

Пригласительный токен действует `INVITATION_TTL_HOURS`, показывается только при
создании ссылки и хранится в PostgreSQL только как SHA-256. Повторное или истёкшее
приглашение отклоняется в транзакции. Один нормализованный email может быть участником
разных проектов, но не может быть добавлен дважды в один проект.

Роль создаётся как `draft` с каноническим SHA-256, затем отдельно публикуется.
Опубликованный JSON и provenance защищены PostgreSQL trigger от изменения и удаления.
Участнику можно назначить несколько точных версий ролей; первая становится основной.

Локальная спецификация оценки фиксирует точные ссылки и checksum конфигурации 4К,
методологию, период, число кейсов и получателей результата. Статус `published`
означает неизменяемость локального snapshot, но не runtime-допуск: до проверки через
API 4К snapshot содержит `runtime_admission=pending_agent4k_verification`, а назначение
не получает `external_cycle_id`.

При принятии приглашения бот вызывает
`POST /integration/v1/participants/resolve` и сохраняет полученный внутренний ID 4К.
Если 4К недоступен, участие в проекте сохраняется, а связывание можно безопасно
повторить командой `/link_4k CODE`. Email и Telegram ID не включаются в ответ API.

## Архитектурные правила

- `telegram_user_id`, а не username, является идентификатором Telegram.
- Email — технический ключ интеграции, а не идентификатор Telegram и не внешний ключ БД.
- Системные права (`admin`, `participant`) отделены от ролей CRISP-DM.
- Один участник может иметь несколько проектных ролей.
- Опубликованные роли и спецификации неизменяемы; изменения создают новую версию.
- Назначение фиксирует точные версии роли и спецификации оценки.
- Участник может получить не более одного нового кейса за локальную дату проекта.
- Ответы и результаты оценки не пишутся в обычные application logs.
- При недоступной интеграции с 4К выдача кейса завершается ошибкой, без встроенной
  предметной подмены.
